The problem

An academic passport that cannot be checked

APAAR IDs are issued, stored and reconciled by hand across thousands of institutions. That process reliably produces four failure modes — and leaves verifiers, employers and universities with no offline way to detect any of them.

Layer 1

Garbage identifiers

Wrong length, placeholder values, failing the checksum — all issued as valid records.

Layer 2

Intakes beyond sanction

Programmes filled well past the intake AICTE approved, with nothing to catch it.

Layer 3

Supernumerary abuse

NRI, OCI, FN and TFW quotas quietly breached — and PMSSS uncapped per course.

Layer 4

Duplicate & unsanctioned enrolment

One APAAR enrolled at two institutions, or at a programme never approved to run.

Solution

A four-layer anomaly engine

Every record is checked against four independent layers. A single failure is a warning; a pattern across records is a finding — and both are surfaced with the evidence attached.

01

APAAR syntactic check

Length must be exactly 12 digits, the value must be non-trivial and not a known placeholder. The Luhn checksum is evaluated and reported as an advisory warning — never a hard reject — so genuine edge cases still get through for human review.

02

Intake breach

Enrolled count compared against the programme’s sanctioned intake for the academic year. The dashboard animates the utilisation gauge so a breach is visible before it becomes a finding.

03

Supernumerary quota ceilings

NRI ≤ 5% · OCI / FN ≤ 15% · TFW ≤ 5% · PMSSS capped per course and institute. Computed against live enrolment, with the offending rows listed by name.

04

Cross-institution multi-enrolment

The same APAAR appearing at two institutions is flagged as DUPLICATE_CROSS_COLLEGE; enrolment at a programme the institution was never approved to run is flagged as UNSANCTIONED_PROGRAM.

Tamper-evident by construction

A scanned QR card proves the record behind it

Each enrolment is sealed with a 32-character digest over the facts the APAAR was issued against. Change any bound field and the seal changes with it. 

# seal = first 32 hex chars of the digest
SHA-256("APAAR|{id}|{institution}|{program}|{year}|{date}")
  .hexdigest()[:32]

The QR matrix itself is produced by a dependency-free ISO/IEC 18004 encoder — Reed–Solomon error correction included — and rendered directly on a Compose Canvas. No third-party QR library is used anywhere in the app.

CSV intake schema

The bulk intake contract — nine columns, one row per student: 

APAAR_ID,Full_Name,DOB,Gender,
Roll_No,Program_Code,Category,
Nationality,Doc_Number

Every row returns a verdict — MISSING_NAME, INVALID_APAAR, LUHN_ADVISORY, DUPLICATE, UNKNOWN_PROGRAM, CATEGORY_MISMATCH — plus an aggregate per-programme impact summary before anything is committed.

Under the hood

Modern Android, deliberately offline

Clean architecture with a Room-backed repository and a single state holder. The app ships with a deterministic seeded pan-India dataset so every screen, anomaly and failure mode is demonstrable with no network at all.

Kotlin 2.2.21 Jetpack Compose Material 3 Room 2.8.5 + KSP Coroutines & Flow Navigation Compose AGP 8.13.2 Gradle 8.14.6 minSdk 24 targetSdk 36

Clean architecture

Domain, data and UI layers with a single ApaarRepository and one ApaarViewModel exposing immutable state through StateFlow.

Deterministic data

12 institutions, 30 programmes and 2,219 students seeded with crafted anomalies — the same every launch.

Proven QR

The round-trip suite decodes the encoder output with an independently written ISO 18004 reference decoder and asserts zero Reed–Solomon syndromes.

Room schema shipped

Every schema version is committed to the repository, so migrations are reviewable in the pull request.

Build it

Clone, build, verify

Requires JDK 17+ and an Android SDK with compileSdk 36. Add a local.properties pointing at your SDK, then: 

# clone
git clone https://github.com/kumaribaishnabidas/EduSynC.git
cd EduSynC/Acadentrix

# run the 78 unit tests and assemble the debug APK
./gradlew testDebugUnitTest assembleDebug
