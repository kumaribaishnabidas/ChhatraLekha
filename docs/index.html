The problem

An academic passport that cannot be checked

APAAR IDs are issued, stored and reconciled by hand across thousands of institutions. That process reliably produces four failure modes — and leaves verifiers, employers and universities with no offline way to detect any of them.

Layer 1

Garbage identifiers

Wrong length, placeholder values, failing the checksum — all issued as valid records.

Layer 2

Intakes beyond sanction

Programmes filled well past the intake AICTE approved, with nothing to catch it.

Layer 3

Supernumerary abuse

NRI, OCI, FN and TFW quotas quietly breached — and PMSSS uncapped per course.

Layer 4

Duplicate & unsanctioned enrolment

One APAAR enrolled at two institutions, or at a programme never approved to run.

Solution

A ten-layer anomaly engine, and a correction that never surprises you

Every record is checked against ten independent layers. A single failure is a warning; a pattern across records is a finding — and both are surfaced with the evidence attached. When a record does have to be corrected, the change impact detector shows exactly what else would be affected before anything is written.

01

APAAR syntactic check

Length must be exactly 12 digits, the value must be non-trivial and not a known placeholder. The Luhn checksum is evaluated and reported as an advisory warning — never a hard reject — so genuine edge cases still get through for human review.

02

Identity: the same student, twice

One APAAR active at two institutions, twice inside one institution, or two students sharing one institute roll number. A cross-institution collision is reported as a potential conflict for review — never as a conclusion.

03

Capacity: intake and the supernumerary ceilings

Enrolled count against the programme’s sanctioned intake, and NRI ≤ 5% · OCI / FN ≤ 15% · TFW ≤ 5% · PMSSS capped per course. The ceilings are versioned policy configuration, not code, so a rule change is a reviewable data change.

04

Integrity: consistency, dates, fields, programmes

Missing foreign-national documents, a quota bucket that contradicts the declared nationality, impossible dates, missing mandatory fields, and enrolment in a course the institution was never approved to run.

05

Change impact detection

Preview a correction and see the six deterministic rules that apply — the seat counts to recalculate, the findings to revisit, the credentials to re-seal. The previous version is kept, and a linked record is never changed silently.

Tamper-evident by construction

A scanned QR card proves the record behind it

Each enrolment is sealed with a digest over the facts the APAAR was issued against. Change any bound field and the seal changes with it. The badge carries an opaque, expiring, revocable token rather than the raw APAAR ID, so a scanned link discloses nothing on its own. 

# HMAC-SHA256 or Ed25519 over the bound fields
"APAAR|{id}|{institution}|{program}|{year}|{date}|
 {name}|{dob}|{gender}|{quota}|{nationality}|{roll}|{version}"

The wire format is <ALG>.<keyId>.<signature>, so a legacy unkeyed digest, an HMAC seal and an offline-verifiable Ed25519 signature all coexist without breaking the badges already in circulation. The private key never leaves the server; the Android client renders the QR matrix with a dependency-free ISO/IEC 18004 encoder — Reed–Solomon error correction included — directly on a Compose Canvas.

CSV intake schema

The bulk intake contract — nine columns, one row per student: 

APAAR_ID,Full_Name,DOB,Gender,
Roll_No,Program_Code,Category,
Nationality,Doc_Number

Every row returns a verdict — MISSING_NAME, INVALID_APAAR, LUHN_ADVISORY, DUPLICATE, UNKNOWN_PROGRAM, CATEGORY_MISMATCH — plus an aggregate per-programme impact summary before anything is committed.

Under the hood

Three parts, one set of rules

A React web application, a Python backend on MongoDB, and an offline-first Android client. The APAAR validator, the anomaly engine, the seal format and the QR payload are specified identically in the Kotlin and Python implementations, so the phone and the server can never disagree about whether a record is valid.

Change impact detection

Six deterministic rules preview what a correction would affect. The previous version is kept and a linked record is never changed silently.

Opaque tokens

A badge carries an expiring, revocable token, stored only as a hash. The public answer is an allowlist and never an APAAR ID.

Deterministic data

12 institutions, 60 programme seats and ~1,900 students seeded with crafted anomalies — the same every launch, on the server and on the phone.

Proven QR

The round-trip suite decodes the encoder output with an independently written ISO 18004 reference decoder and asserts zero Reed–Solomon syndromes.

Build it

Clone, build, verify

The backend needs Python 3.11+ and a MongoDB server; the frontend needs Node 20+; the Android client needs JDK 17+ and an Android SDK with compileSdk 36. Add a local.properties pointing at your SDK, then: 

# clone
git clone https://github.com/kumaribaishnabidas/EduSynC.git

# the backend
cd EduSynC/edusync
pip install -r requirements.txt
cp .env.example .env            # then edit the secrets
python -m app.scripts.seed      # synthetic demo dataset
uvicorn app.main:app --reload
pytest -q                       # 217 tests

# the web frontend
cd ../frontend
npm install
npm test                        # 31 tests
npm run build

# the Android client
cd ../Acadentrix
./gradlew testDebugUnitTest assembleDebug
