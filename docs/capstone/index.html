How ChhatraLekha works

A guided tour from a synthetic CSV batch to a private, verifiable credential — with deterministic rules, reviewable corrections and a grounded AI assistant at every step.

Not an official registry. ChhatraLekha is an educational prototype. It is not affiliated with APAAR, AICTE, CBSE or any government body. Every dataset shown here is synthetic.

The five-step workflow

Each step is a separate, testable operation. Nothing is written or published until an authorised user explicitly commits it.

1

Ingest synthetic data

Upload a CSV batch. The parser validates mandatory columns, APAAR format, dates, quota, programme and seat impact.

Preview ≠ write
2

Detect anomalies

Ten deterministic rule layers check identifiers, duplicates, intake, NRI/PMISSS ceilings, nationality rules and missing fields. Each finding names its rule and evidence.

Explainable
3

Review & correct

Preview the impact of a proposed correction with no write side effect, then apply it against the expected record version. Review work is recorded in the audit trail.

Version-checked
4

Verify privately

An opaque, expiring token replaces the student identifier. Public verification returns an allowlisted response and withholds personal fields unless consent is active.

No APAAR ID exposed
5

Explain with AI

The assistant retrieves reviewed documentation locally with TF-IDF, cites its sources and answers record questions only from the caller's authorised data.

Grounded · offline by default

Why the assistant is "grounded"

Retrieval always runs locally. A generator is optional (deterministic templates by default; Ollama or Gemini are opt-in). Prompt injection, provider errors, unsafe output and empty context all fall back to the reviewed answer — the assistant fails closed rather than inventing.

Next milestone: labeled benchmark

The synthetic anomaly benchmark measures agreement with explicit labels. It cannot establish real-world accuracy or prove that a flagged record is fraudulent.

Per-rule metrics

precision = TP / (TP + FP) recall = TP / (TP + FN) F1 = 2 × precision × recall / (precision + recall)

Use N/A when a denominator is zero. Record dataset size, labelling procedure, rule configuration, commit SHA and the exact command. Report timing only as a machine-specific measurement.

Limits. Android and Linux checks were not run in this environment; npm run lint cannot run because eslint is not installed. Frontend tests must be run sequentially with the backend suite to avoid 5-second timeout flakiness.
